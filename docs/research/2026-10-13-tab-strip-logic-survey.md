# Tab Strip 正常逻辑调研（Chrome / Firefox / VS Code / Edge / JetBrains）

2026-10-13 · 背景：SessionStrip 改造（无滚动条 + 收缩 + ⋯ 溢出菜单）后需要一份"正常 tab 条应该怎么行为"的对照基准。

## 1. 宽度模型（核心分歧点）

| 产品 | 模型 | 最小宽 | 触底后 |
|---|---|---|---|
| Chrome/Edge | 全 tab 等分收缩 | ~72px 内容宽 | 新 tab 出屏右侧（不换行），关闭钮先在非活跃 tab 上消失保 favicon/标题 |
| Firefox | 固定地板 | 76px | 两端出现滚动箭头按钮 + 「列出全部 tab」下拉 |
| VS Code | `tabSizing` 三档：fit（不缩，滚）/ shrink（min 40px）/ fixed | 默认 fit | 溢出进 `›` 下拉（仅溢出时显示） |
| Safari | 等分收缩（同 Chrome） | ~icon | 同 Chrome |
| JetBrains | 单行收缩 | 有下限 | 溢出进 ⋯ 菜单 |

**无一家有数量上限**——保护是视觉层的（收缩地板 + 溢出承接），不是数字上限。

## 2. 逐维度行为契约

| 维度 | 业界一致行为 |
|---|---|
| 新 tab 位置 | 追加到最右端，**立即激活并滚入视野**（Chrome 会把 strip 滚到底） |
| 激活恒可见 | 任何程序化激活（含外部跳转）都把该 tab scroll 进视口 |
| 关闭后激活谁 | 右邻居（末位则左邻居）；部分产品（VS Code 可选）用最近使用序 |
| 关闭时布局 | Chrome「tab slinky」：关闭后其余 tab **保持原宽直到鼠标离开 strip**，连续点 × 都在同一位置命中下一个 tab |
| 滚动条 | **永不显示**；滚轮 → 横向滚动 |
| 溢出菜单 | Firefox/VS Code：仅溢出时出现；Chrome：⌄「搜索标签」**常显**在标题栏 |
| 窄 tab 牺牲序 | 关闭钮（非活跃先消失）→ 标题 → 只剩 icon/圆点；标题到 0 之前必须先藏关闭钮 |
| 拖拽重排 | 都有（本 strip 暂无） |
| 中键关闭 | 浏览器都有（本 strip 暂无） |

## 3. 对本 strip（SessionStrip）的差距评估

已对齐：无可见滚动条 / 滚轮横向化 / 激活滚入视野 / ⋯ 溢出菜单（VS Code 语义）/ 收缩地板。

已知差距（按价值排序）：
1. ~~收缩地板过低（72px → 标题 8px 不可读）~~ 已修 2026-10-13（104px）
2. **窄 tab 不藏关闭钮**——Chrome 在窄非活跃 tab 上先藏 × 保标题；我们的 × 恒定占位 ~16px
3. **无 tab slinky**——连续关闭时 tab 立即重排，第二个 × 点不中（小样本高频操作）
4. 新 tab 滚入视野依赖 `activeViewId` effect + Kobalte Trigger ref 转发，未验证（dev 环境实证过创建可见，但未覆盖"overflow 态新建")
5. 溢出菜单仅溢出时出现（VS Code 语义）；Chrome 常显语义可作选项

## 4. 结论

"正常 tab"的核心不变量：**数量无上限；可读性有地板；溢出必有非滚动条承接；新建/激活必可见；关闭不挪鼠标目标**。
