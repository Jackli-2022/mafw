## 交付内容

### 1. 受信调用记录

- kernel 只识别 canonical `tool.call` 且 `tool === 'skill'`；skill 名取 `input.name`，回退 `skill`/`id`。
- `callID` 必填；`skill_invocations` 按 callID 去重（`INSERT OR IGNORE`）。
- 成功调用默认 `outcome='unknown'`：加载 SKILL.md 不等于任务成功。
- `tool.result` 的 `isError=true` 只把同一 callID 标为 `failure`（机械失败）；非错误结果不改 outcome。
- 列表/搜索/读取 SKILL.md 不产生调用记录。

### 2. 调用统计

`GET /api/skills`（operationId `skills.list`, internal）返回注册表行 +：

```json
{
  "stats": { "total": 0, "success": 0, "failure": 0, "unknown": 0, "lastAt": null }
}
```

### 3. 健康 deopt

每周 `memory:skillPromotion` 扫描后追加健康检查（纯函数 `shouldDeoptSkill`）：

- 所有 `source_memory_ids` 都不存在或被 supersede → `source-superseded`
- `failure >= 3` 且 `success === 0` → `repeated-failure`
- 空 source 列表不算 evidence，不 deopt；成功次数 >0 不因失败 deopt
- 命中后走 6A 的目录移动 + registry `paused`

heartbeat counts 增加 `deopted`。

### 4. 语义边界

- 只有 runtime/host 事件算调用；文本相似度、候选目录、读取 SKILL.md 都不算。
- 成功仍只可能由机械检查、Goal verdict 或人工验收确认；6B 尚未接入 Goal verdict，因此绝大多数调用保持 `unknown`。
- deopt 在下一发现/激活边界生效，不撤回已注入上下文。
