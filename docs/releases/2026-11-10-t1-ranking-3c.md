## 交付内容

### 1. 激活批量读取

`GatewayDatabase.t1Activations(traceIds)`：

- 去重、忽略空/未知 id、最多 100 个参数。
- 返回 `Map<traceId, activation>`；查询失败返回空 Map（fail-open）。

### 2. 有界重排

`applyT1ActivationRanking(hits, opts)`：

```text
eligible = activation > 0 && baseScore >= topScore × band
score    = eligible ? baseScore × (1 + weight × min(1, activation)) : baseScore
```

- `band` 默认 `0.6`（clamp 0–1）：带外命中永远不会被提升。
- `weight` 默认 `0.1`，硬上限 `0.2`：最多 20% 相对提升。
- 只对 dense/lexical 已经召回的命中重排，不能新增结果。
- 排序稳定：同分按原始顺序。

### 3. 三档模式

```text
config.recall.t1Recall.activationRanking:
  off     — 不查询 activation，不改变顺序
  shadow  — 计算并计数 wouldReorder，返回原顺序（默认）
  on      — 返回有界重排后的顺序
```

`off` 不调用 `t1Activations`。失败一律回退相关性顺序。

### 4. 观测

`/api/memory/stats` 的 `t1` 新增：

```json
{
  "activationRanking": {
    "mode": "shadow",
    "evaluations": 0,
    "wouldReorder": 0,
    "applied": 0
  }
}
```

`evaluations` 统计参与评估的 T1 搜索结果数；`wouldReorder`/`applied` 区分 shadow 与 on。用于决定是否把默认切到 `on`。

## 已知限制

- activation 增量仍是固定值，不是 ACT-R 的 `ln(sum t^-d)`；排序只消费状态，不反推校准。
- `shadow` 的 `wouldReorder` 只累计在进程内，重启清零；跨天 A/B 需要外部采样 stats。
- 排序只作用于 T1 搜索结果；T1-only 快照在构建时使用同一搜索函数，因此也会继承模式（默认 shadow 不改顺序）。
