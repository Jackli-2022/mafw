# MAFW v4.1 Architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the current MAFW plugin + Gateway implementation into full compliance with `MAFW_Architecture_v4.1_FINAL.md`, making the Phase Relay loop, Gateway常驻模式, Git worktree isolation, three-tier memory, and dashboard operational end-to-end.

**Architecture:** The plugin remains the OpenCode integration surface (commands, hooks, tools, skills). The Gateway becomes a real system-level daemon that owns OpenCode Serve lifecycle, polls `state/*.json`, creates/destroys phase sessions, and exposes a dashboard. All business state transitions are written explicitly by Skill Entry functions; Gateway only reads `nextAction`.

**Tech Stack:** TypeScript, Node.js >=18, `simple-git`, `js-yaml`, `axios` (already in use). Jest for tests. PowerShell/batch on Windows for service registration.

## Global Constraints

- All production authentication code must use RS256 (AGENTS.md §3.1).
- Code without >=80% test coverage must be marked `DEGRADED` unless tagged `prototype` or `spike` (AGENTS.md §3.2).
- Every feature must have boundary tests: null, oversized input, special characters, timing attacks (AGENTS.md §3.3).
- Do not modify user `opencode.json` automatically (architecture doc §5.3).
- Gateway must not contain business logic: no verdict parsing, no loop counting beyond `maxLoops`, no prompt assembly.
- All state writes must be atomic (tmp file + rename).
- Commit scope ∈ {gateway, plugin, connector, memory, docs, automation}.
