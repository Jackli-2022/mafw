# MAFW v5.0 Wave 1 — Infrastructure + Retrieval + Storage

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Upgrade the current MAFW v4.1 codebase with the v5.0 infrastructure layer: configuration system, energy system, hybrid retrieval (BM25 + Vector + RRF), token budget allocation, and a unified `mafw_search_hybrid` tool that powers context injection.

**Architecture:** Keep existing plugin surface (commands, hooks, tools) and Gateway scheduler unchanged. Layer new modules on top. The `experimental.chat.messages.transform` hook is upgraded to use the new retrieval pipeline, but the `/goal` command and Gateway state machine remain the same.

**Tech Stack:** TypeScript, Node.js >=18, `simple-git`, `@xenova/transformers` (new for Vector Index). Jest for tests.

## Global Constraints

- All production authentication code must use RS256 (AGENTS.md §3.1).
- Code without >=80% test coverage must be marked `DEGRADED` unless tagged `prototype` or `spike` (AGENTS.md §3.2).
- Every feature must have boundary tests: null, oversized input, special characters (AGENTS.md §3.3).
- Do not modify user `opencode.json` automatically.
- All state writes must be atomic (tmp file + rename).
- Gateway must not contain business logic (verdict, loop counting, prompt assembly).
- Commit scope ∈ {gateway, plugin, connector, memory, docs, automation}.
