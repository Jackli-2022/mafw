# Skill v1 Phase 6B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record trusted skill invocations from runtime `tool.call` events, keep success `unknown` unless mechanically proven, expose invocation statistics, and deopt skills whose source knowledge is gone or whose calls repeatedly fail at the tool boundary.

**Architecture:** A pure extractor recognizes canonical `tool.call` events with `tool='skill'` and an input skill name. The kernel writes `skill_invocations` rows (deduped by callID); `tool.result` errors mark the same row failed, while a successful load stays `unknown`. `GET /api/skills` lists registry rows with stats. The weekly promotion action also runs a health pass that deopts source-superseded skills and skills with repeated tool failures.

**Tech Stack:** TypeScript, better-sqlite3, Jest.

**Spec:** `docs/superpowers/specs/2026-11-10-t1-experience-knowledge-skill-design.md` §8.2 / §12 step 6.

## Global Constraints

- Only runtime/host events count. Searching, listing, or reading `SKILL.md` must never create an invocation row.
- A successful `skill` tool call means the skill was activated/loaded, **not** that the task succeeded. Success stays `unknown` unless a mechanical check or Goal verdict later proves it.
- `tool.result` errors may mark a call `failure` (mechanical failure); never infer success from a non-error result.
- Missing/ambiguous skill name or callID → no row (fail-closed on identity).
- Deopt remains a directory move + registry status; effective at the next discovery boundary.
- No new executable permissions or auto-execution.

## Review Focus

- A non-skill tool event with the same callID must not create/alter an invocation row.
- Two events for the same call must dedupe by callID.
- A `tool.result` error for an unknown/non-skill callID is a no-op.
- Listing/reading a skill must not increment usage.
- Deopt must not fire on a single transient failure, and must retain the archived directory.

## Explicit Non-Goals (6C)

- Goal-verdict linkage that upgrades invocations to success.
- Candidate discovery based on invocation outcomes.
- Canary/AB or automatic promotion.
- Immediate revocation of injected instructions.
- Executable/write-capable skills.
