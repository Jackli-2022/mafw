# MAFW v5.0 Wave 3 — Concurrency + Knowledge Graph + Dashboard

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the MAFW v5.0 upgrade with multi-agent concurrency, knowledge graph integration, and a full web dashboard.

**Architecture:** All three modules are independent. Dashboard runs in the Gateway process. Knowledge graph integrates into the hybrid search pipeline. Concurrency extends the Loop/Wave state machine.

**Tech Stack:** TypeScript, Node.js, `ws` (WebSocket), Chart.js (CDN), better-sqlite3 (existing).

---

## Task 1: Multi-Agent Concurrency (~2 days)

### Step 1: StateLockManager (`src/engine/state-lock.ts`)

- [ ] `acquireLock(goalId, loopNum, waveNum, agentId, timeout?)` — in-memory lock with expiry
- [ ] `releaseLock(goalId, loopNum, waveNum)` — release and clean up
- [ ] `heartbeat(goalId, loopNum, waveNum)` — extend lock expiry
- [ ] Automatic stale lock cleanup (periodic sweep)

### Step 2: WaveDependencyManager (`src/engine/wave-dependency.ts`)

- [ ] `waveDependency(waveNum, dependsOn: number[])` — declare dependencies
- [ ] `canStartWave(goalId, loopNum, waveNum)` — check deps are completed
- [ ] `updateWaveStatus(goalId, loopNum, waveNum, status)` — track progress
- [ ] `getReadyWaves(goalId, loopNum)` — return waves whose deps are satisfied
- [ ] `getBlockedWaves(goalId, loopNum)` — return waves still waiting

### Step 3: OptimisticStateSync (`src/engine/optimistic-sync.ts`)

- [ ] Version-based file updates via temp + rename
- [ ] `updateState(goalId, patch, expectedVersion)` — returns boolean
- [ ] Conflict detection and retry guidance

### Step 4: Integration

- [ ] Wire `WaveDependencyManager` into `mafw-execute` wave loop
- [ ] Wire `StateLockManager.acquireLock()` before task branch creation
- [ ] Wire `handleLoopEvent` to check `getReadyWaves()`

## Task 2: Knowledge Graph (~3 days)

### Step 1: Types (`src/graph/types.ts`)

- [ ] `GraphNode`, `GraphEdge`, `KnowledgeGraph` interfaces
- [ ] Node types: concept / entity / fact / pattern
- [ ] Relation types: depends_on / uses / causes / part_of / implements / tests / co_occurs

### Step 2: EntityExtractor (`src/graph/entity-extractor.ts`)

- [ ] Rule-based extraction from text (technology keywords, file extensions)
- [ ] `extract(text)` → string[] of concept/entity names
- [ ] `extractWithLLM?` placeholder for future enhancement

### Step 3: RelationInferencer (`src/graph/relation-inferencer.ts`)

- [ ] Co-occurrence relation: same-sentence entities → `co_occurs` edge
- [ ] Dependency keywords: `depends on` / `requires` / `uses` → `depends_on` edge
- [ ] Cause keywords: `error` / `fix` / `bug` / `issue` → `causes` edge
- [ ] `inferRelations(entities, context)` → GraphEdge[]

### Step 4: GraphSearcher (`src/graph/graph-searcher.ts`)

- [ ] BFS traversal from query nodes, maxDepth=2
- [ ] Simplified PageRank via incoming edge weights
- [ ] `search(queryNodes, maxDepth)` → GraphNode[]
- [ ] `calculateImportance(nodeId)` → number

### Step 5: Graph Storage

- [ ] `KnowledgeGraphManager` — addNode, addEdge, removeNode
- [ ] Persist to JSON file (`.mafw/data/knowledge-graph.json`)
- [ ] Load on startup, save on mutation

### Step 6: Integration with Hybrid Search

- [ ] In `mafw_search_hybrid` tool: if `config.retrieval.graph.enabled`
- [ ] Extract entities from query text via EntityExtractor
- [ ] Search graph via GraphSearcher
- [ ] Pass graphResults into `reciprocalRankFusion` (already supports 3 lists)
