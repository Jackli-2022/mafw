# GitHub CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Jackli-2022/mafw 搭建三个 GitHub Actions workflow：验证（ci.yml，双 OS）、Desktop 制品 draft Release（desktop-release.yml，Win+Linux）、npm 发布留接口（npm-publish.yml，token 缺失优雅 skip）。

**Architecture:** 三个独立 workflow 文件（方案 A，触发语义解耦）。验证跑 root build + gateway jest + TUI node --test；Desktop 打包复用现有 `package:win`/`package:linux` npm scripts（bun stage-gateway + electron-builder，`--publish never` 由汇总 job 统一上传 draft release）；npm publish 带 NPM_TOKEN guard。附带一处 electron-builder 配置修复：`native/` extraResource 目录仓库中不存在，加 `existsSync` 条件守卫防 CI 打包失败。

**Tech Stack:** GitHub Actions（actions/checkout@v4、setup-node@v4、setup-bun@v2、cache@v4、upload/download-artifact@v4、softprops/action-gh-release@v2）、js-yaml（本地 YAML 校验）、bun test（electron-builder 配置测试）、gh CLI（观察运行结果）。

**Spec:** `docs/superpowers/specs/2026-09-14-github-ci-design.md`（commit eb61fcd2）

## Global Constraints

- Node 全线 22（runner 上解析为最新 22.x ≥ 22.19，满足 TUI type-stripping engines）
- gateway 不是 root workspace 成员且有独立 lockfile：安装永远两段式（root `npm ci` + gateway/ `npm ci`）
- `OPENCODE_CHANNEL=prod` 必须用 step 级 `env:` 块设置（Windows runner 无 bash 内联 `VAR=x cmd` 语法）
- Desktop 打包命令必须带 `-- --publish never` 尾参（防 electron-builder 自行上传，上传统一收敛到 release job）
- ci.yml concurrency cancel-in-progress；desktop-release concurrency 不 cancel
- npm-publish：`NPM_TOKEN` 缺失 → 输出 skipped 并绿过，绝不误发布
- v1 非目标：macOS 制品、mobile、evaluation、root jest、desktop typecheck（tsgo）
- 本地不预先加 `--forceExit`（gateway/tests 已无 kernel/python 集成测试，AGENTS.md 提示过时）；仅当本地 pre-flight 挂住才加 `-- --forceExit`
- 全部任务直接 commit 到本地 main（用户既定流程，无 PR）；**push 到 origin 只发生在 Task 5 且须先获得用户确认**
- 不需要任何 secret 即可让 ci.yml / desktop-release.yml 工作；npm-publish.yml 无 NPM_TOKEN 时 skip 绿过

- Produces: 修改后 config 的 `extraResources` 语义——`native/` 目录存在才含 `{from:"native/",to:"native/",filter:[...]}` entry；`gateway-bundle/` 两个 entry 恒在。Task 3 的打包步骤依赖此语义。

- [ ] **Step 1: 写失败测试**

创建 `packages/desktop/electron-builder.resources.test.ts`：

```ts
import { expect, test } from "bun:test"
import { $ } from "bun"
import type { Configuration } from "electron-builder"

type ResourceEntry = { from: string; to: string; filter?: string[] }

const listResources = async (config: Configuration): Promise<ResourceEntry[]> =>
  (config.extraResources ?? []) as ResourceEntry[]

test("omits native/ extra resource when the directory is absent", async () => {
  const module = await import("./electron-builder.config.ts?native-absent=1")
  const resources = await listResources(module.default as Configuration)
  expect(resources.some((r) => r.to === "native/")).toBe(false)
  expect(resources).toContainEqual({ from: "gateway-bundle/", to: "gateway/" })
})

test("includes native/ extra resource when the directory exists", async () => {
  await $`mkdir -p native`.quiet()
  try {
    await Bun.write("native/index.js", "// marker\n")
    const module = await import("./electron-builder.config.ts?native-present=1")
    const resources = await listResources(module.default as Configuration)
    expect(resources).toContainEqual({
      from: "native/",
      to: "native/",
      filter: ["index.js", "index.d.ts", "build/Release/mac_window.node", "swift-build/**"],
    })
  } finally {
    await $`rm -rf native`.quiet()
  }
})
```

### Task 2: ci.yml（验证 workflow）

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: 现有 npm scripts——root `build`（tsc + gateway + tui）、`test`（gateway jest --runInBand）、`test:tui`（node --test）
- Produces: push(main)/PR 触发的 `verify` job；Task 5 的 push 后观察依赖它

- [ ] **Step 1: 创建 workflow 文件**

`.github/workflows/ci.yml` 完整内容：

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: build + test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    timeout-minutes: 45
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: |
            package-lock.json
            gateway/package-lock.json

      - name: Install root deps
        run: npm ci

      - name: Install gateway deps
        working-directory: gateway
        run: npm ci

      - name: Build (plugin + gateway + tui)
        run: npm run build

      - name: Test gateway
        run: npm test

      - name: Test TUI
        run: npm run test:tui
```

（注：root `npm ci` 的 postinstall 会自动给 gateway 装 prod deps，随后的 gateway `npm ci` 整体重装 dev+prod——双重安装多花约 1 分钟，换取与本地开发流一致的确定性，可接受。）

- [ ] **Step 2: YAML 本地校验**

Run（workdir 仓库根）:

```bash
node -e "const y=require('js-yaml'),fs=require('fs');const f='.github/workflows/ci.yml';const d=y.load(fs.readFileSync(f,'utf8'));if(!d||!d.name||!d.jobs||!d.jobs.verify)throw new Error('structure check failed');console.log(f,'OK, jobs:',Object.keys(d.jobs).join(','))"
```

Expected: `.github/workflows/ci.yml OK, jobs: verify`
（只校验 `jobs`/`name`，不碰 `on:` 键——js-yaml 对 YAML 1.1 的 `on` 有 bool 化怪癖，GitHub 自身解析正常。）

### Task 3: desktop-release.yml（Desktop 制品 workflow）

**Files:**
- Create: `.github/workflows/desktop-release.yml`

**Interfaces:**
- Consumes: Task 1 的 config 守卫（无 native/ 目录也能打包）；desktop 现有 scripts `build`（prebuild bun 脚本从 git 跟踪的 `icons/<channel>/` 生成 `resources/icons`）与 `package:win`/`package:linux`（bun stage-gateway + electron-builder）；root `npm run build` 产出的 `gateway/dist`
- Produces: tag `v*` push → draft release 附 Win(nsis)/Linux(AppImage/deb/rpm) 制品；workflow_dispatch → 仅构建 + artifacts。Task 5 的 dry-run 依赖它

- [ ] **Step 1: 创建 workflow 文件**

`.github/workflows/desktop-release.yml` 完整内容：

```yaml
name: Desktop Release

on:
  push:
    tags: ["v*"]
  workflow_dispatch:

concurrency:
  group: desktop-release-${{ github.ref }}

permissions:
  contents: write

jobs:
  build:
    name: package (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    timeout-minutes: 60
    strategy:
      fail-fast: false
      matrix:
        os: [windows-latest, ubuntu-latest]
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: |
            package-lock.json
            gateway/package-lock.json

      - uses: oven-sh/setup-bun@v2

      - name: Cache electron binaries (Linux)
        if: runner.os == 'Linux'
        uses: actions/cache@v4
        with:
          path: ~/.cache/electron
          key: electron-linux-${{ hashFiles('packages/desktop/package.json') }}

      - name: Cache electron-builder (Linux)
        if: runner.os == 'Linux'
        uses: actions/cache@v4
        with:
          path: ~/.cache/electron-builder
          key: electron-builder-linux-${{ hashFiles('packages/desktop/package.json') }}

      - name: Cache electron binaries (Windows)
        if: runner.os == 'Windows'
        uses: actions/cache@v4
        with:
          path: ~/AppData/Local/electron/Cache
          key: electron-win-${{ hashFiles('packages/desktop/package.json') }}

      - name: Cache electron-builder (Windows)
        if: runner.os == 'Windows'
        uses: actions/cache@v4
        with:
          path: ~/AppData/Local/electron-builder/Cache
          key: electron-builder-win-${{ hashFiles('packages/desktop/package.json') }}

      - name: Install root deps
        run: npm ci

      - name: Install gateway deps
        working-directory: gateway
        run: npm ci

      - name: Build root (plugin + gateway + tui)
        run: npm run build

      - name: Build desktop (electron-vite)
        working-directory: packages/desktop
        run: npm run build

      - name: Package desktop (windows)
        if: runner.os == 'Windows'
        working-directory: packages/desktop
        env:
          OPENCODE_CHANNEL: prod
        run: npm run package:win -- --publish never

      - name: Package desktop (linux)
        if: runner.os == 'Linux'
        working-directory: packages/desktop
        env:
          OPENCODE_CHANNEL: prod
        run: npm run package:linux -- --publish never

      - name: Upload artifacts
        uses: actions/upload-artifact@v4
        with:
          name: desktop-${{ runner.os }}
          path: |
            packages/desktop/dist/*.exe
            packages/desktop/dist/*.blockmap
            packages/desktop/dist/*.AppImage
            packages/desktop/dist/*.deb
            packages/desktop/dist/*.rpm
            packages/desktop/dist/latest*.yml
          if-no-files-found: error

  release:
    name: attach artifacts to draft release
    needs: build
    if: startsWith(github.ref, 'refs/tags/')
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/download-artifact@v4
        with:
          path: dist
          merge-multiple: true

      - uses: softprops/action-gh-release@v2
        with:
          draft: true
          files: |
            dist/*.exe
            dist/*.blockmap
            dist/*.AppImage
            dist/*.deb
            dist/*.rpm
            dist/latest*.yml
```

要点（实现者须知）：
- `npm run package:win -- --publish never` 把尾参追加到脚本行末 → `electron-builder --win --config electron-builder.config.ts --publish never`，覆盖 prod channel config 里的 GitHub publisher
- `OPENCODE_CHANNEL: prod` 走 step `env:` 块（Global Constraints）
- upload 的 `if-no-files-found: error` 是"整个 pattern 集零命中"才报错；exe/AppImage/deb/rpm 必在，`latest*.yml` 若被 `--publish never` 抑制也只是少传，不炸
- `workflow_dispatch`（无 tag）触发时 release job 被 `if: startsWith(github.ref, 'refs/tags/')` 跳过 = 构建-only 干跑通道

Run（workdir 仓库根）:

```bash

```

Expected: `.github/workflows/desktop-release.yml OK, jobs: build,release`

### Task 4: npm-publish.yml（发布接口 workflow）

**Files:**
- Create: `.github/workflows/npm-publish.yml`

**Interfaces:**
- Consumes: root `npm run build`（publish 的 `prepare` 钩子会再跑一次 build——幂等）；secrets `NPM_TOKEN`（可缺）
- Produces: 手动 dispatch 的 `publish` job；无 token 绿 skip

- [ ] **Step 1: 创建 workflow 文件**

`.github/workflows/npm-publish.yml` 完整内容：

```yaml
name: npm publish

on:
  workflow_dispatch:

permissions:
  contents: read
  id-token: write

jobs:
  publish:
    name: publish opencode-plugin-mafw
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - name: Check NPM_TOKEN
        env:
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
        run: |
          if [ -z "$NPM_TOKEN" ]; then
            echo "SKIP=true" >> "$GITHUB_ENV"
            echo "npm publish skipped: NPM_TOKEN not configured"
          fi

      - uses: actions/checkout@v4
        if: env.SKIP != 'true'

      - uses: actions/setup-node@v4
        if: env.SKIP != 'true'
        with:
          node-version: 22
          registry-url: https://registry.npmjs.org
          cache: npm
          cache-dependency-path: |
            package-lock.json
            gateway/package-lock.json

      - name: Install root deps
        if: env.SKIP != 'true'
        run: npm ci

      - name: Install gateway deps
        if: env.SKIP != 'true'
        working-directory: gateway
        run: npm ci

      - name: Build
        if: env.SKIP != 'true'
        run: npm run build

      - name: Publish
        if: env.SKIP != 'true'
        run: npm publish --provenance --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

（`id-token: write` 供 `--provenance` 生成来源证明。guard step 无 token 时写 `SKIP=true` 进 `$GITHUB_ENV`，后续步骤全部 `if: env.SKIP != 'true'` 跳过，job 绿色结束。）
