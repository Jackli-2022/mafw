# T1 Activation Ranking Phase 3C Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consume T1 trace activation as a bounded re-rank *inside the relevance band only*, with `off | shadow | on` modes (default `shadow`), so ordering never changes until explicitly enabled and hot traces can never rescue irrelevant results.

**Architecture:** `fuseT1Hits` stays the relevance authority. A pure `applyT1ActivationRanking` boosts only hits whose RRF score is at least `band × topScore` (default 0.6) by at most `weight × activation` (default 10%). `shadow` computes the would-be order but serves the original; `on` serves the new order. Module counters expose evaluations/reorders for A/B stats.

**Tech Stack:** TypeScript, Jest.

**Spec:** `docs/superpowers/specs/2026-11-10-t1-experience-knowledge-skill-design.md` §6.1.

## Global Constraints

- `off`: no activation lookup, no ordering change.
- `shadow` (default): compute would-be order, serve original order, count `wouldReorder`.
- `on`: serve the bounded order.
- Activation can only re-rank hits already returned by dense/lexical; it can never add hits or lift a hit below `band × topScore`.
- Weight cap: default 0.1, hard max 0.2.
- Any lookup/compute failure is fail-open to the relevance order.
- No energy/snapshot/injection change.

## Review Focus

- A high-activation but far-less-relevant hit must not move (Task 2 band gate).
- `shadow` must be observationally identical to `off` in payload order (Task 2).
- Missing/unknown traces default to activation 0 (Task 1).
- Lookup failure must not break T1 search (Task 2).
