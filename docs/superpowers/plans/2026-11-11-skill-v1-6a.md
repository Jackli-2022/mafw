# Skill v1 Phase 6A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn W2's memory→SKILL.md materialization into a capability pipeline: drafts carry an explicit playbook contract, installs are recorded in a capability registry with version/status/source ids, and deopt moves the skill out of discovery scope at the next boundary.

**Architecture:** A deterministic contract extractor parses triggers/inputs/outputs/steps/tools/permissions/success/failure/scope from the procedural memory and its anchors. `renderSkillMd` emits the contract in frontmatter + body. Promotion refuses drafts whose contract lacks triggers/steps/scope. The installer records `skill_registry` rows; deopt renames the skill directory into `.disabled/` and marks the registry row paused/deprecated. No executable script permission is added.

**Tech Stack:** TypeScript, js-yaml, better-sqlite3, Jest.

**Spec:** `docs/superpowers/specs/2026-11-10-t1-experience-knowledge-skill-design.md` §8 / §12 step 6.

## Global Constraints

- v1 is natural-language playbook only: no scripts, no write operations, no auto-execution.
- Existing staging + triage human approval remains the only promotion path.
- A draft must contain triggers, stable steps, scope, source memory/trace ids, version and status; missing required fields block staging.
- Deopt takes effect at the next discovery/activation boundary (directory moved), never claims to retract already-injected instructions.
- Trusted invocation/success events are **not available** from the runtime in v1; usage stays `unknown`, never inferred from search/read/text similarity.
- All new paths are fail-open except contract validation (a malformed draft must not be staged).

## Review Focus

- A procedural memory with no numbered steps must not silently become a skill.
- Source memory ids/trace ids must survive into the installed registry row.
- A paused/deopted skill must disappear from the runtime skill directory atomically.
- Reinstalling the same name must bump the registry version rather than resetting it.
- Human-confirmed install must remain the only writer of active rows.

**Interfaces:**

```ts
export interface SkillContract {
  triggers: string[];
  negativeTriggers: string[];
  inputs: string[];
  outputs: string[];
  steps: string[];
  tools: string[];
  permissions: string[];
  successCriteria: string[];
  failureHandling: string[];
  scope: string[];
}

export function extractSkillContract(unit: {
  memory_value: string;
  cue_anchors?: string[];
  source_session_id?: string;
}): SkillContract;

export function validateSkillContract(c: SkillContract): { valid: boolean; errors: string[] };
```

- Parsing: markdown headings (`## 触发 / Triggers` etc.) + bullet lists; fallback triggers from non-namespaced cue anchors; fallback scope `session:<source_session_id>`; `steps` from numbered/bulleted lines outside contract sections, requiring ≥2.
- Validation: `triggers ≥1`, `steps ≥2`, `scope ≥1`; everything else may be empty but renders as an explicit “待补充” section.
- `renderSkillMd(unit, contract)` writes YAML frontmatter keys: `name`, `description`, `version: 1`, `status: staging`, `source_memory_ids`, `source_trace_ids`, `triggers`, `negative_triggers`, `inputs`, `outputs`, `tools`, `permissions`, `success_criteria`, `failure_handling`, `scope`, plus a readable body.

## Explicit Non-Goals (6B)

- Trusted skill activation/invocation events and success statistics.
- Automatic candidate discovery from execution outcomes.
- Skill version UI, canary/AB, or automatic promotion.
- Executable/write-capable skills.
- Immediate revocation of already-injected instructions.
