# MAFW v6.6 Memory Restructure — Global L5 + `.mafw/` Migration

> **Goal**: Restructure memory system storage: move project-level MAFW data from `.opencode/mafw/` to `.mafw/`, flatten T2/T3/T4 into single `memories.json`, and extract L5 to global `~/.mafw/l5/` owned by Gateway.

## Architecture

```
v6.4 (current)
  {projectDir}/.opencode/mafw/
  ├── memory/tier3/{goalId}.json       ← goal_id 绑定, 多层嵌套
  ├── memory/.harmonic_index.json      ← 含 goal_id 字段
  ├── state/{goalId}.json
  ├── parametric/{goalId}.yaml
  └── ...

▼

v6.6 (target)
  {projectDir}/.mafw/                  ← ★ 整个 mafwDir 搬移
  ├── memory/
  │   ├── observations/                ← T1 按天分片
  │   ├── memories.json                ← T2+T3+T4 合并, 无 goalId
  │   ├── .harmonic_index.json         ← 无 goal_id
  │   └── .cognitive_graph.json        ← 统一路径
  ├── state/  parametric/  goals/
  ├── lessons/  reviews/  receipts/
  └── config.yaml

  ~/.mafw/l5/                          ← ★ 全局，Gateway 持有
  ├── axioms.json
  └── heuristics.json
```

## Key Decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | L5 at `~/.mafw/l5/` (global), not project-level `{project}/.mafw/l5/` | Cross-project sharing; Gateway is the persistent service |
| 2 | `.mafw/` replaces `.opencode/mafw/` entirely | Single root, cleaner path, consistent with docs |
| 3 | Fresh start: no migration of old `.opencode/mafw/` data | Avoid complexity; old data preserved as backup |
| 4 | Phase D last: path migration after L5 infrastructure | Reduce rollback risk; isolate concerns |

## Data Model Changes

### `HarmonicUnit` — Remove `goal_id`, keep `type` as discriminator

```typescript
interface HarmonicUnit {
  id: string;
  // goal_id REMOVED — project isolation is now physical (directory)
  type: 'episodic' | 'semantic' | 'procedural';  // replaces memory_type; 'global' → L5Store
  primary_abstraction: string;
  cue_anchors: string[];
  memory_value: string;
  energy: number;
  salience?: number;
  abstraction_level?: number;
  review_count?: number;
  last_reviewed?: string;
  associations?: string[];
  created_at: string;
  updated_at: string;
}
```

> `type` field preserved so episodic/semantic/procedural can still be filtered or displayed differently. All types share the same `memories.json` file.

### L5 Types (new)

```typescript
interface L5Axiom {
  id: string;
  content: string;
  source: string;        // 'manual' | 'distilled'
  created_at: string;
  energy: number;
}

interface L5Heuristic {
  id: string;
  pattern: string;
  trigger_context: string[];
  success_rate: number;
  source_goal_ids: string[];
  energy: number;
  created_at: string;
}
```

## Implementation Plan (4 Phases)

### Phase A — L5 Infrastructure

**New files:**
- `src/utils/global-path.ts` — `findGlobalMafwDir(): string`
- `src/memory/l5-store.ts` — `L5Store` class

**`findGlobalMafwDir()` logic:**
```
os.homedir() + '/.mafw'
Windows: %USERPROFILE%\.mafw
```

**`L5Store` API:**
- `loadAxioms(): L5Axiom[]`
- `addAxiom(content, source): L5Axiom`
- `loadHeuristics(): L5Heuristic[]`
- `addHeuristic(pattern, triggerContext, sourceGoalIds): L5Heuristic`
- `getTop(topK): { axioms: L5Axiom[], heuristics: L5Heuristic[] }`

### Phase B — Gateway L5 Integration

**Modified files:**
- `gateway/src/memory/service.ts` — add `L5Store` field
- `gateway/src/types.ts` — extend `MemoryService` with L5
- `gateway/src/mcp/tool-registry.ts` — register new L5 tools
- `gateway/src/mcp/handlers/` — new handlers

**New MCP tools:**
- `mafw_commit_heuristic` — write L5 heuristic
- `mafw_get_axioms` — read L5 axioms

**Dashboard API:**
- `GET /api/l5/axioms` — list axioms
- `GET /api/l5/heuristics` — list heuristics

### Phase C — T4→L5 Distillation

**Modified files:**
- `src/memory/abstraction-distiller.ts` — implement `distillT4toL5()`
- `src/memory/l5-store.ts` — may need batch import method

**Logic:**
- Scan `memories.json` for T4 entries with successRate > 0.9
- Group by pattern similarity
- ≥5 matching T4 → promote to L5 heuristic
- Write via `L5Store.addHeuristic()`

### Phase D — `.mafw/` Migration + Memory Flattening

**Modified files (~60):**

| Area | Key changes |
|---|---|
| `src/plugin.ts` | `mafwDir` from `.opencode/mafw` → `.mafw` |
| `src/compression/hybrid-compressor.ts` | Write to `memories.json` not `tier{N}.json` |
| `src/memory/harmonic-index.ts` | Remove `goal_id` from index entries |
| `src/memory/harmonic-types.ts` | Remove `goal_id` from `HarmonicUnit` |
| `src/memory/cognitive-graph.ts` | Path to `.mafw/memory/.cognitive_graph.json` |
| `gateway/src/*` | Sync `mafwDir` paths |
| `gateway/src/dashboard/api.ts` | Update `mafwDir` from `.opencode/mafw` → `.mafw` |
| `gateway/src/index.ts` | Update `mafwDir` in `initServices()` |
| All other `path.join(mafwDir, ...)` | Batch replace |

**Migration script:**
- Create `.mafw/` directory structure
- Old `.opencode/mafw/` left untouched as fallback
- Print deprecation warning if old path still used after N days

## Scope Clarifications

| In scope | Out of scope (deferred) |
|---|---|
| `L5Store` CRUD for `~/.mafw/l5/{axioms,heuristics}.json` | T1 observation buffer infrastructure (directory exists in target tree but not implemented) |
| T4→L5 distillation logic | MinHash cross-project merge |
| Memory flattening: tier files → `memories.json` | Cognitive graph rebuild from associations field |
| `mafwDir` path migration `.opencode/mafw` → `.mafw` | Old `.opencode/mafw/` auto-cleanup |
| L5 MCP tools + Dashboard API | `observations/` date-sharded JSONL writer |

## Rollback Strategy

- Phase A-C: revert by deleting new files, no data loss
- Phase D: old `.opencode/mafw/` still exists — revert by switching `mafwDir` back

## Decision Log

| # | Decision | Rationale |
|---|---|---|
| 1 | Phase D last | L5 is independent; path migration is mechanical bulk work |
| 2 | Fresh `.mafw/` not symlink | Simpler, no migration complexity |
| 3 | L5 types separate from HarmonicUnit | L5 is conceptually different (global axiom vs project memory) |
| 4 | No backward compat for old path | Clean break; old dir preserved as manual fallback |
