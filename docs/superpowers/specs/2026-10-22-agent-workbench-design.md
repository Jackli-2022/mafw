# Agent Workbench：右侧 Dock 升级为人机协同桌面 — 设计 spec

2026-10-22 · 状态：待用户确认

## 1. 意图与 Why

**定义时刻**：agent 在 MAFW 里干活，用户被迫"出舱"验收——切 VSCode 看代码、开浏览器查结果、另开终端跑命令。验收循环发生在产品之外，chat client 的定义撑不住这个现实。

**产品定义上移**：MAFW 从"opencode 桌面客户端"上移为**人机协同的 agent 工作台**（AgentOS 类比中的"窗口管理器"层：子代理/后台任务 = 进程管理，记忆 = 内存管理，工具/权限 = 系统调用，而 UI 是 agent 与人共用的桌面）。在这个定义下：

- **chat 降级为"喊话器"**——发起与追踪工作的通道；
- **右侧 dock 升级为"桌面"**——agent 干活的地方，人验收与协同的地方。

## 2. 总原则：同一个实例

右侧 dock 的每个面板都是**看进 agent 工作环境的一个窗口**，人和 agent 操作的是同一份文件、同一个终端、同一个环境——不是镜像、不是摘要。

## 3. 五件套全景

| 面板 | 角色 | 关键依赖 | 期 |
|---|---|---|---|
| 文件浏览器 | 入口：找到要看的文件 | desktop main 进程 fs IPC | 一期 |
| 协同编辑器 | **核心交互**：人标出 → agent 改 → 原地验收 | session-ui `line-comment*` 原语（P0-2 转正） | 一期 |
| terminal | 共享命令面 | v2 `/api/shell` 通道（P0-3 已摸熟） | 二期 |
| 网页浏览器 | 同页协同 | Electron webview（简单版）；agent 工具链同步（完整版） | 二期（简单版）/ 三期+ |
| 沙箱环境 | 隔离执行底座 + CUA 舞台 | Linux 容器/发行版 + 项目目录挂载 + 屏幕流 | 三期 |

CUA（computer use）进沙箱是三期的主要动机——解决当前 CUA"用户亮屏 + 占住键鼠"的痛点——但 **CUA 的具体方案本 spec 不覆盖**（用户明确暂缓，届时单独立项）。

## 4. Goals / Non-goals / Anti-goals

**Goals**
- G1：用户在 MAFW 内完成"看 agent 改了什么、查了什么"的验收闭环，不切 VSCode/浏览器。
- G2：核心协同交互落地：**人标出（选中代码 + 一句话）→ agent 改 → 原地验收**。
- G3：沙箱环境承接 agent 的全部执行（命令、未来的 CUA），用户桌面不被占用、不被污染。

**Non-goals**
- N1：CUA 具体方案（视觉管线、AT-SPI/X11、屏幕流协议）——三期立项时再定。
- N2：持久化行级批注（评论挂在代码行上、可攒多条再提交）——一期只做即发即消耗。
- N3：浏览器与 agent 的"同一页"深度同步（agent 浏览工具 ↔ 用户视口）——三期+。
- N4：terminal 的多会话管理/tmux 式布局——二期只做单会话共享。
- N5：沙箱内的完整 IDE 体验（调试器、LSP 全套）——编辑器是协同界面，不是 VSCode 替代品。

**Anti-goals**
- A1（最重要）：**agent 的爆炸半径不得超过挂载的项目目录**。沙箱方案无论选什么技术，项目目录之外的系统、应用、个人文件必须不可触及。一期虽不涉及沙箱，但后续任何沙箱设计以此为准入门槛。
- A2：不做"又一个 chat 面板"——右侧的价值在于操作同一实例，纯信息展示 tab 不属于本方向。

## 5. 一期范围：文件浏览器 + 协同编辑器

纯 desktop 工程（renderer + main IPC），**不动 gateway、不动 runtime、不动词汇**。

### 5.1 文件浏览器（dock 新 tab「文件」）

- 展示**当前项目目录**（对应现有项目管理：项目 = 目录，session 带 `directory`）的文件树。
- 只读导航：展开/折叠/点击文件 → 在协同编辑器中打开；不建/删/改文件（一期）。
- 性能：懒加载目录层级；大目录不递归预取。

### 5.2 协同编辑器（dock 新 tab「编辑器」/ 与文件浏览器联动）

- 打开项目内文本文件，语法高亮，**可编辑**（VSCode 式：脏缓冲区 + Ctrl+S 显式保存；缓冲区干净时外部改动静默刷新，有未保存编辑时弹冲突提示——agent 改用户正开着的文件是核心循环的必然事件，用 fs.watch 监听，绝不静默覆盖用户编辑）。
- **标注即发即消耗 · 直发**（用户已确认的取舍，Builder Check Q1=A）：选中代码 → 弹出输入框写一句话 → **立即** `promptAsync` 发给当前活动会话（复用 P0-2 已有的 diff-comment 管线；会话忙时走 `turn-queue`），消息内嵌文件路径 + 行范围 + 选中内容的结构化引用。不经过 composer、不持久化。（composer 草稿模式 = 二期增强，与持久批注共用附件子系统地基。）
- agent 改完后**原地验收**：编辑器内打开 diff 视图（复用 ChangesDock 的 diff 数据通路），diff 行级评论（`line-comment*` 组件转正）作为"标注"在 diff 载体上的同构能力——**P0-2 不做单独返工，并入本期**。pi runtime 下 `session.diff` 能力门 503 → 按 Gate Ruling A 惯例降级（提示能力缺失，不为 pi 自建 git 通道）。
- **文件树根跟随活动会话的 directory**（Builder Check Q2 裁定）：普通会话=项目目录，worktree 会话=worktree 目录——标注与 diff 永远指向 agent 实际看到的文件树（§2"同一个实例"原则的推论）。
- RightDock 变为**可调宽度**：编辑器 tab 激活时可拉宽（上限约窗口 50%），其余 tab 保持现有窄栏。

### 5.3 一期验收判据

1. 不切 VSCode：在 dock 里浏览当前会话目录的文件、打开、编辑、Ctrl+S 保存；agent 改了正开着的文件时出现外部改动提示（缓冲区脏）或静默刷新（缓冲区干净）。
2. 选中代码 + 一句话 → 消息立即发出，agent 的输入中含文件路径 + 行号范围 + 选中内容，回答能定位到该段代码。
3. agent 改完文件后，编辑器内可看到该文件的 diff 并逐行评论、发送（v2 runtime；pi 下显示能力缺失提示）。
4. desktop 全量测试 + tsgo + build 全绿（遵循仓库 TDD 惯例）。

## 6. 二期、三期轮廓（不在本期交付，仅锚定方向）

- **二期 terminal**：dock 新 tab，xterm.js 前端 + v2 `/api/shell` 会话（P0-3 的 wire 契约与 SDK 管道现成）；人与 agent 共享同一 shell 会话，谁敲的命令都可见。
- **二期/三期 浏览器**：Electron `<webview>` 内嵌简单版先行；"和 agent 看同一页"依赖沙箱期（浏览器跑在沙箱里，双方看同一块屏幕）。
- **三期 沙箱**：Linux 容器/专用发行版（用户已确认可 Linux，UIA 复用非约束）；**挂载当前项目目录**（对应项目管理）；爆炸半径 ≤ 项目目录（A1）；VM 屏幕流嵌 dock 作为 CUA 观察/接管窗口；一期只做"agent 命令在沙箱跑"，二期再做"人也能登进去"。

## 7. 已决事项（用户拍板）

| 决策 | 内容 |
|---|---|
| 产品定义 | 上移为 agent 工作台；chat=喊话器，右侧=桌面 |
| 核心交互 | 人标出 → agent 改 → 原地验收 |
| 标注形态 | 一期即发即消耗 · **直发**（Builder Check Q1=A）；composer 草稿/持久批注二期+ |
| 文件树根 | 跟随活动会话 directory（含 worktree），保证标注/diff 与 agent 视图一致（Q2） |
| pi runtime | 一期 diff 能力降级提示（Q3，Gate Ruling A 惯例） |
| 保存语义 | 脏缓冲区 + Ctrl+S；fs.watch 外部改动：干净→静默刷新，脏→冲突提示（Q4） |
| 沙箱隔离 | 是属性不是技术选型；挂载模式；爆炸半径 ≤ 项目目录 |
| 沙箱 OS | 可 Linux（不为复用 UIA 强上 Windows） |
| CUA | 暂缓，三期立项再议 |
| P0-2 | 不单独返工，并入一期协同编辑器 |

## 8. Builder 的自由度（我的 call，可在实现期调整）

- 编辑器组件选型（Monaco / CodeMirror / 自研轻量）——建议先评估 session-ui 现有依赖再定。
- fs IPC 的具体形状（main 进程新 channel，参照现有 `window.api.mafw.*` 模式）。
- dock 拉宽的交互细节（拖拽手柄 vs 预设档位）。
- 标注消息在 composer 的具体呈现（引用块样式）。

## 9. 风险与备注

- **写文件的安全性**：编辑器直接写真文件，误编辑无 undo 栈兜底——依赖编辑器自身的 undo（组件内）+ git。一期不做自动快照。
- **大文件**：编辑器设大小上限（如 1MB），超出降级只读。
- **与 P0-2 的关系**：`line-comment*` 组件在 session-ui 库内未接线，本期首次接线，diff 数据通路（`onSendComment`）已在。
- 既有未决事项不受影响：gateway v2 鉴权桥（Gate Ruling A）、restart-agent 500/sidecar v2 ready 行（并行工作流）。
