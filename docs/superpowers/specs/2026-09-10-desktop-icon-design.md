# MAFW Desktop 图标重设计 — 设计文档

日期：2026-09-10
状态：已实施（29/29 测试通过；构建脚本 `packages/desktop/scripts/build_icons.py`）

## 1. 背景

`packages/desktop` 现有图标继承自 opencode（开关造型），与 MAFW 品牌零关联。
本次重设计为 MAFW 独立品牌形象，方向：**二次元女性角色（mascot）图标**。

## 2. 角色设定「茉芙 / Mafu」（波形歌姬）

**名字**：MAFW 读作 "ma-fu" → 拟音为中文名「茉芙」（茉莉+芙蓉），罗马音 Mafu。
**设定**：Memory-Augmented Framework for Work 的调律者——她耳机里听到的不是
音乐，是你的记忆谐波。

结合项目特点的意象映射：

| 项目特性 | 角色元素 |
|---|---|
| 谐波记忆（harmonic） | 耳罩外侧发光正弦波形 |
| MAFW 名字 | 波形即字母：**M=双波峰、W=双波谷**，耳罩波形上半 M 峰、下半 W 谷；刘海中央分出一缕 A 形银发（标志彩蛋）；F 元素克制不用（仅周边物料可用） |
| 能量系统（energy） | 发色高光、光环 halo 的发光感 |
| 智能体工作台 | 包耳式耳机（operator 气质） |

- **性格**：成熟冷艳（early-20s 气质，不 Q 不萌系）
- **发型**：银白长发内扣，发梢带青→紫罗兰渐变
- **眼**：蓝色、正视观众、冷静自信、微哂
- **耳机**：哑光黑包耳式，耳罩发光青紫正弦波形（单一记忆点）
- **背景**：深空蓝黑（#0E1220）+ 头后青色光环 halo，无多余元素

## 3. 业界调研结论（2026-09-10）

- 二次元角色图标业界先例充分：MAA（阿米娅头像特写）、哔哩哔哩、手游行业惯例
- 关键规范：脸部占图标高度 60-75%、正视或微侧（眼神接触）、背景极简、
  单一高对比记忆点、桌面平台直角满血出血构图（macOS 套 squircle 遮罩，Windows/Linux 直角）
- 抽象符号派（ChatGPT/Claude/Cursor）与本项目用户选择的 mascot 方向不冲突，
  借鉴其"单一记忆点 + 高对比"原则

## 4. 选定基础图

- 文件：`packages/desktop/icons/concepts/icon-concept-zhipu-2.png`（1024×1024）
- 生成链路：智谱 CogView-4-250304（经 `zhipuai-coding-plan` key），
  生成脚本存于 `%TEMP%\opencode\gen_icon_zhipu.py`（临时，实施时固化到仓库）
- 选择理由：正面构图、脸部占比最大、耳罩波形最清晰、气质符合"成熟冷艳"

**合规调研（2026-09-10，依据官方原文）**：

依据《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，2025-09-01 施行，
网信办官网原文）：
- 显式水印是**服务提供者**（智谱）按第 4 条履行的义务（图片适当位置显著标识）
- 第 9 条给出**正规无水印路径**：用户可申请服务提供者提供不含显式标识的内容，
  服务提供者通过用户协议明确用户标识义务后即可提供（即智谱侧可能有企业版/
  协议版无水印输出，需向智谱确认）
- 第 10 条：用户**发布** AI 生成内容应主动声明；任何组织和个人不得**恶意**
  删除、篡改、伪造、隐匿标识（关键词"恶意"——以非误导目的处理自有品牌资产
  不属恶意，但保守做法是声明）
- 适用范围上，桌面应用图标是品牌资产而非"网络信息内容传播"场景，动漫角色
  也不属深度合成规定第 17 条"可能导致公众混淆误认"的拟真情形（人脸/真人声），
  监管风险低

**本案采纳方案（分级）**：
- 首选：后处理移除可见水印 + 保留/补写隐式元数据标识 + 在应用关于页或
  分发渠道声明"图标由 AI 辅助生成"（对齐第 10 条主动声明精神）
- 更稳：向智谱确认其服务协议是否提供无显式标识内容申请通道（第 9 条）
- 最稳：以 AI 图为底稿做实质性人工二次创作（精修/重绘），产物即人机合作
  创作物，超出"生成合成内容"范畴

## 5. 后处理与产出管线

### 5.1 主图后处理（Pillow 脚本，固化到 `packages/desktop/scripts/build-icons.ts` 或 `scripts/`）

1. **水印处理**：右下角"AI生成"水印区域做内容感知式覆盖（采样邻近深色
   像素做镜像/模糊填充；该区域为深色背景+发梢，无关键内容，不裁剪画布）
2. **icns 安全边距**：选定图发梢出血到边缘；为 macOS Big Sur squircle 遮罩
   生成 `icon.icns` 时，将主图缩放至 ~88% 居中置于 1024 画布（背景色采样
   边缘深色延展），形成 ~6% 安全边距；其他平台产物不缩放（出血构图）
2. **渠道变体**（沿用现有 prod/dev/beta 三渠道结构，`scripts/copy-icons.ts`）：
   - `prod`：标准版
   - `dev`：叠加 blueprint 网格底纹 + 蓝色调（延续现有 dev "蓝图"语言）
   - `beta`：角色不变，右上角叠加橙色 "BETA" 角标
3. **尺寸矩阵**（自 1024 主图下采样）：
   - 通用 PNG：32/64/128/128@2x/256/512/1024
   - `icon.ico`（Windows，内嵌 16/24/32/48/64/128/256，Pillow 可写）
   - `icon.icns`（macOS，Pillow IcnsImagePlugin 可写；用 §5.1-2 的
     带安全边距版本生成）
   - `dock.png`（Electron 未打包时 `app.dock.setIcon` 用，256px）
   - Windows Store Square*Logo / ios/ android/ 目录：本次**不重新生成**
     （desktop 应用不打包移动端/商店版，避免无验证的批量产出）
4. **替换目标**：`packages/desktop/icons/{prod,dev,beta}/` 核心文件
   （icon.png / icon.ico / icon.icns / dock.png / 32/64/128/128@2x PNG）
5. **文档更新**：`packages/desktop/icons/README.md` 现存流程是 Tauri 时代的
   （`bun tauri icon` + Image2Icon），已失效，重写为新管线说明

### 5.2 验证

- 读回各尺寸 PNG 目检（尤其 32×32 脸部可辨度）
- `electron-builder.config.ts` 引用的 `resources/icons/icon.ico|icns` 由
  `prebuild` 从 `icons/{channel}` 拷贝，无需改配置
- 构建一次 desktop（`npx electron-vite build`）确认资源链路不报错（不打包安装器）

## 6. 不做的事（YAGNI）

- 不重新生成 ios/android/Windows Store 图标
- 不做动态/动画图标
- 不改 `electron-builder.config.ts`、`copy-icons.ts` 流程结构
- 不为 favicon/public 下 web 资产换图（那些是 <100B 的占位文件，非本次范围）

## 7. 角色设定复用

本角色「茉芙 / Mafu」是 MAFW 官方吉祥物，可在 dashboard 关于页、启动页、
文档、社交物料中复用；复用时遵循 §2 设定表保持一致性（名字、发色、耳机
M/W 波形、A 形发丝彩蛋），并用同一 prompt 模板再生成。
