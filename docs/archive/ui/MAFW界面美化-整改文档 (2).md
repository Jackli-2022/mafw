# MAFW 界面美化 — 实现偏差整改文档

> 依据：实现版暗/亮截图 vs 《MAFW界面美化-开发文档》v2 + 《任务列表面板组件-开发文档》。
> 已对齐的部分（双主题、导航 pill、侧栏选中指示条、会话 Tab、Agent 头、Send 主按钮、build pill 真实值）不再列出，本文只列**偏差项**，按优先级排序。

---

## P0 — 结构错误（布局不对，必须改）

### P0-1 Tasks 面板：定位错误，遮挡输入框

| 项 | 内容 |
|---|---|
| 现象 | 面板宽度约为输入框一半、右对齐、**绝对定位悬浮并压住了 Composer 的顶部边框**（暗/亮截图均可见） |
| 规格 | 文档 §4.6：面板在**文档流内**位于 Composer 上方 12px，**与 Composer 同宽**（760px 居中对齐），只有出现/消失动画，不遮挡任何内容 |
| 修改 | `TaskPanel` 去掉 absolute/fixed 定位与 right 偏移，改为输入区容器（包裹 Composer 的那个 760px 居中 wrapper）的**普通流式第一个子元素**：`width:100%; margin-bottom:12px`。这样 z-index、遮挡、消息列表底部预留 padding 三个问题同时消失 |
| 验收 | 面板左右缘与 Composer 完全对齐；面板出现时 Composer 被自然下推，无任何遮挡 |

### P0-2 Composer：工具条跑到容器外面了

| 项 | 内容 |
|---|---|
| 现象 | `+`、`@`、`build ⌄`、Send 按钮在输入框**外部下方**自成一行；输入框本身是一个独立的高盒子，placeholder 顶对齐、下方大片空白 |
| 规格 | 文档 §4.7：**容器 = textarea + 底部工具条**，同一个 `--bg-float` 圆角 16px 带边框的盒子；聚焦描边/光晕作用于整个容器（`:focus-within`）；空态最小高 52px |
| 修改 | DOM 调整为：`div.composer(border/radius/bg) > textarea(无边框无背景) + div.toolbar(h-44px, flex)`。聚焦样式从 textarea 移到容器的 `:focus-within`。工具条不再占独立行宽、不再与输入框分离 |
| 验收 | 空态整个 Composer 高 ≈96px（52 textarea + 44 工具条）；聚焦时整个外框一圈绿，不是只有 textarea |

### P0-3 侧栏底部 "connected :3000" 重复 + 横向滚动条

| 项 | 内容 |
|---|---|
| 现象 | 侧栏底部状态条出现**两次**（Rail 底部一条 + 窗口最底部还有一条）；且暗色下侧栏底部有一条**水平滚动条**（内容横向溢出） |
| 规格 | 文档 §4.3：状态条仅一条，高 32px，位于侧栏内底部 |
| 修改 | **合并而非裸删**：保留 Rail 底部状态条为全窗口唯一状态条，把根 StatusBar 的 failed 态 **restart 按钮**与**右键菜单**迁移过来（三态规格见美化文档 §4.3 底部状态栏）；迁移完成后才删根 StatusBar。Rail 容器加 `overflow-x:hidden`（列表项确保 `min-w-0` + `truncate`），消除横向溢出 |
| 验收 | 全窗口仅一处 connected；任意窗口宽度下侧栏无横向滚动条 |

## P1 — 规格偏差（样式/行为不对）

### P1-1 Tasks 面板计时在任务完成后仍跳动

| 项 | 内容 |
|---|---|
| 现象 | 任务已 1/1 全部完成（绿勾），耗时仍从 7m45s → 8m1s 继续累加 |
| 规格 | Tasks 文档 §5：指标在运行中刷新；运行结束应**冻结在最终耗时** |
| 修改 | elapsed ticker 绑定 run 状态：`status === 'running'` 才累加；全部完成/中断时停止并保留终值；新 run 重置为 0 |

### P1-2 完成态任务行缺删除线

| 项 | 内容 |
|---|---|
| 现象 | 完成行只有绿勾 + 文字变灰，无删除线 |
| 规格 | Tasks 文档 §4.1：completed = 勾选圆 + **整行删除线**（含 chip）+ `--text-completed` |
| 修改 | 行内容加 `line-through`（`text-decoration-color` 同色 70% 透明）。**勾的颜色**：Tasks 文档写蓝 `#136FF4`，MAFW 主题下统一用 `--accent` 绿更协调——**此处以品牌一致优先，保留绿勾**，视为对 Tasks 文档的本地化覆盖，仅补删除线 |

### P1-3 用户气泡样式不达标

| 项 | 内容 |
|---|---|
| 现象 | 气泡是无边框、小 padding、统一圆角的小 pill；暗色下与背景对比过低，边界几乎不可见 |
| 规格 | 文档 §4.5：`--bg-overlay` 底 + **1px `--border-subtle`** + 圆角 **16/16/4/16**（右下小角）+ padding **10px 14px** + max-width 70% + 14px `--text-1` |
| 修改 | 按规格补齐四项；暗色下若边框仍不清晰，气泡底可上调半档（`--bg-float`）——以"一眼可辨边界"为准 |

### P1-4 侧栏会话时间戳溢出换行

| 项 | 内容 |
|---|---|
| 现象 | 第 4 个 Manager 会话下方掉出一行 "2026/8/3 01:00:59"，与"今天"分组头挤在一起（暗/亮均可见） |
| 规格 | 文档 §4.3：行内 meta 信息不换行，空间不足时隐藏或 truncate |
| 修改 | 会话行的时间戳元素加 `white-space:nowrap; flex-shrink:0`；行宽不足时按文档 §4.3 历史行的做法：默认显示日期、hover 时让位给 "⋯" 操作按钮；**禁止 wrap 到第二行** |

## P2 — Polish（可随下一轮）

| # | 现象 | 建议 |
|---|---|---|
| P2-0 | **层级颜色不可辨**：四级背景明度差太小（v2 色板 5% 级差），侧栏/聊天区/卡片/浮层看起来一个色 | 色板已升级 v3：暗色四级改为 `07/0E/16/1F`（7–9% 级差），文字、品牌绿、hover/边框同步提亮——**全量同步 `mafw.css` 变量定义**（暗色 :root 与亮色两套都换），值见《MAFW界面美化-开发文档》§3.1–3.4 |
| P2-1 | 标题栏暗色主题图标渲染成"C"形（moon 路径缺口朝向问题，看着像字母 C） | 调整 moon 图标 path（月牙缺口朝右上），或改用与原型一致的月牙形状 |
| P2-2 | 暗色下 Composer 边框几乎不可见，像一块纯黑区域 | 确认 `--border-subtle` 是否被旧样式覆盖；`border` 声明需带 `1px solid var(--border-subtle)`，不是只写颜色 |
| P2-3 | placeholder 为"输入消息…"（原型是 "Type a message…"） | 不算偏差，产品文案自行决定；断连态的 "Reconnecting…" 文案同步用中文即可 |

## 整改顺序建议

1. **P0-2 Composer 结构**（DOM 调整，影响最大、其它项的依附点）
2. **P0-1 Tasks 面板归位**（依赖 1 的容器结构）
3. **P0-3 状态条去重 + 横向滚动**
4. P1 四项（独立小改，可并行）
5. P2 随手带过

全部改完后按《MAFW界面美化-开发文档》§7 重新过一遍验收，重点加验三条：**面板与 Composer 左右缘对齐、聚焦绿圈包围整个 Composer、全窗口仅一处 connected**。
