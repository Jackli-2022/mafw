# AskCard 询问卡片组件 — 开发文档

> Agent 运行中需要用户决策时，在聊天流内插入的询问卡片（对应 ask_user / AskUserQuestion 类工具的 UI 承载）。
> 色板全部复用《MAFW界面美化-开发文档》v3 tokens；新增 1 个语义色 `--warning`。
> 定位：比用户气泡重、比 Approvals 页轻——**快问快答在卡片内闭环，复杂审批才进 Approvals**。

---

## 1. 组件概述

```
┌──────────────────────────────────────────────────────┐
│ ?  Manager 需要你的决策                   ● 等待输入   │ ← Header：图标 + 来源 + 状态徽章
│──────────────────────────────────────────────────────│
│ 选择 todo 更新的实现方式？                              │ ← 问题标题 15px/500
│                                                        │
│ ┌──────────────────────────────────────────────────┐ │
│ │ ◉ 扩展 gateway todo API                    推荐  │ │ ← 选中态：accent-dim 底 + 绿描边
│ │   加 POST /session/:id/todo，前后端打通最完整      │ │   选项描述（可选）13px text-3
│ ├──────────────────────────────────────────────────┤ │
│ │ ○ 用 MCP 工具直连 opencode server                 │ │
│ ├──────────────────────────────────────────────────┤ │
│ │ ○ 其他（输入自定义回答）                            │ │
│ └──────────────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 输入你的回答…                                      │ │ ← 仅选中"其他"时出现
│ └──────────────────────────────────────────────────┘ │
│                                              取消  提交 │ ← Footer：ghost + 主按钮
└──────────────────────────────────────────────────────┘
```

### 层次结构

```
AskCard
├── CardHeader      → 状态图标 + "{agent} 需要你的决策" + 状态徽章（等待输入/已回答/已取消）
├── QuestionBlock × 1~3                     ← 支持一次多问
│   ├── QuestionTitle
│   ├── OptionRow × N                       ← radio(单选) / checkbox(多选)
│   │   ├── Mark                            ← 圆圈/方框
│   │   ├── OptionTitle  [+ 推荐徽章]
│   │   └── OptionDesc?                     ← 可选说明
│   └── CustomInput?                        ← "其他"选项展开
└── CardFooter      → 快捷键提示 + 取消 + 提交
```

| Token | 暗 | 亮 | 用途 |
|---|---|---|---|
| `--warning` | `#E7A13D` | `#B87A1E` | "等待输入"徽章、reconnecting 态（与 §4.3 状态栏共用） |

### 2.2 容器与 Header

| 元素 | 规格 |
|---|---|
| 容器 | `--bg-overlay` + 1px `--border-subtle` + 圆角 16px；**左侧 3px `--warning` 竖条**（圆角贴合），标识"需要操作"；位于消息列内，宽 100%（≤760px） |
| Header | 高 40px，padding `0 16px`，下缘 1px `--border-subtle` |

## 3. 状态机

```
pending ──提交──▶ answered
   │──取消──▶ cancelled
   │──会话中断/新 run──▶ expired（自动，视为取消）
```

| 状态 | 视觉 | 交互 |
|---|---|---|
| `pending` | 完整卡片 + warning 竖条 + "等待输入"徽章脉动 | 可选/可输/可提交取消 |
| `answered` | **折叠为单行摘要**：图标变 `--accent` ✓ + 问题标题（truncate）+ 已选答案 chip ×N + "已回答"徽章；warning 竖条移除 | 点击摘要可展开只读回看；不可改 |
| `cancelled` / `expired` | 折叠单行 + "已取消"徽章，整体 60% 透明 | 只读 |

> 摘要单行高 40px：`✓ 选择 todo 更新的实现方式？ → [扩展 gateway todo API]`，答案 chip = `--accent-dim` pill。

**多问场景**：一次最多 3 问，共用一次提交；全部问题都有选择后提交才可用；answered 摘要按问逐行列答案 chip。

## 4. 交互行为

| 交互 | 行为 |
|---|---|
| 点选项行 | 单选：选中该行的同时清除同问其它选择；多选：toggle。过渡 120ms |
| 键盘 | 卡片 pending 且页面无输入焦点时：`1-9` 选择对应选项（按组内序号），`Enter` 提交，`Esc` 取消 |
| 选"其他" | CustomInput 展开（grid-rows 动画 200ms）并自动聚焦；提交时以输入内容为答案；输入为空则提交禁用 |
| 提交 | 卡片 150ms 折叠为 answered 摘要（高度动画），同时把答案作为一条**用户消息**注入聊天流（内容 = 选项标题或自定义文本）——保证会话记录完整、agent 上下文可续 |
| 取消 | 折叠为 cancelled 摘要；agent 侧收到取消信号（工具返回 cancelled） |
| 新卡片出现 | 自动 `scrollIntoView({block:'nearest'})`；若用户正在翻阅历史则不强行滚动，改为 Composer 上方浮一个"有 1 个待回答 ↓"提示 pill |
| 多个 pending 卡片 | 允许并存（不同 run/不同 agent）；不做全局互斥 |

## 5. 数据结构

```ts
type SelectMode = 'single' | 'multi';

interface AskOption {
  id: string;
  title: string;
  description?: string;
  recommended?: boolean;     // 渲染"推荐"徽章并预选中（单问题最多 1 个）
}

interface AskQuestion {
  id: string;
  title: string;             // 问题正文
  mode: SelectMode;
  options: AskOption[];      // 2~4 个；"其他"由组件自动追加，不在此列
  allowCustom?: boolean;     // 默认 true：是否提供"其他"输入
}

interface AskCardData {
  id: string;
  agentName: string;
  status: 'pending' | 'answered' | 'cancelled' | 'expired';
  questions: AskQuestion[];  // 1~3
  answers?: Record<string, string[]>;   // answered 时：questionId → 选中的 optionId 或 ['__custom__']
  customText?: Record<string, string>;
  createdAt: number;
}
```

## 6. 组件 API

```ts
interface AskCardProps {
  data: AskCardData;
  onSubmit?: (answers: Record<string, string[]>, customText: Record<string, string>) => void;
  onCancel?: () => void;
}
```

事件约定：`onSubmit` 后组件进入 answered（由父级回写 status）；`onCancel` 同理。组件本体不持有异步逻辑。

## 7. 边界与异常

| 场景 | 处理 |
|---|---|
| 选项标题超长 | 两行内显示，超出 truncate；描述固定单行 truncate |
| 选项 >4 个 | 选项组 `max-height: 220px` 内部滚动（工具应约束 ≤4，UI 兜底） |
| 全部问题都未选就点提交 | 按钮禁用，不弹错误；键盘 Enter 同样被拦 |
| 会话中断时存在 pending 卡 | run 结束事件统一把 pending → expired |
| 亮/暗主题 | 全部走 tokens；warning 竖条与徽章在两主题下均需可辨（亮色 `--warning` 已加深） |
| 与 Approvals 的分工 | 涉及权限/破坏性操作（删文件、执行命令）走 Approvals 完整审批；**方案选择、参数确认、分叉决策**走 AskCard。不要把权限确认降级成普通提问 |
